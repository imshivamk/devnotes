
- JWT is an open standard (RFC 7519) for securely transmitting information between parties as a JSON object.
- JWTs are "self-contained" tokens that carry all the necessary information for authentication and authorization within the token itself.
- They are especially well-suited for stateless authentication in distributed and scalable backend systems

## **Typical JWT Authentication Flow**

1. User signs in → backend generates JWT → client stores JWT.
2. Client sends JWT in `Authorization` header for every request to protected endpoints.
3. Middleware on backend validates JWT, extracts user info, and attaches it to request context for authorization and business logic

| Step                | Description                                                      |
| ------------------- | ---------------------------------------------------------------- |
| User Login          | User submits credentials to backend                              |
| JWT Issuance        | Backend verifies user, creates signed JWT                        |
| Store JWT           | Client stores JWT (preferably in HTTP-only cookie)               |
| Authenticated Calls | Client sends JWT in `Authorization: Bearer <token>` header       |
| Validation          | Backend verifies JWT signature and claims before granting access |

---
## JWT contents

A JWT consists of 3 parts - separated by dots (`.`)
- **Header:** Algorithm and token type (usually specifies HS256 or RS256 and "JWT").
- **Payload:** Claims, which are statements about the user and any additional data (e.g., user ID, roles, issued at, expiration).
- **Signature:** Ensures the JWT hasn’t been tampered with. Created by hashing the header and payload with a secret key
