## 1. Install Dependencies

```bash
npm init -y
npm i express cors pg dotenv
npm i -D nodemon
```

### Packages

1. express  
    Web framework for Node.js; handles routing, middleware, HTTP layer.
    
2. cors  
    Enables cross-origin requests (React → backend). Without it, browser blocks requests due to same-origin policy.
    
3. pg  
    Official client for PostgreSQL; used to execute SQL queries.
    
4. dotenv  
    Loads environment variables from `.env` into `process.env`.
    
5. nodemon (dev)  
    Auto-restarts server on file changes.

## 2. Setup `.env`

Create `.env` in project root:

```
PGUSER=youruser
PGHOST=localhost
PGDATABASE=yourdb
PGPASSWORD=yourpass
PGPORT=5432
```

### Why `.env`

1. Security: avoids hardcoding credentials.
    
2. Environment isolation: dev/test/prod configs differ.
    
3. Industry standard: used in containers, CI/CD.

## 4. Database Connection (`db.js`)

```js
require("dotenv").config();
const { Pool } = require("pg");

const pool = new Pool({
  user: process.env.PGUSER,
  host: process.env.PGHOST,
  database: process.env.PGDATABASE,
  password: process.env.PGPASSWORD,
  port: process.env.PGPORT,
});

module.exports = pool;
```

## 5. Concept: Connection Pool

### Definition

Pool = a managed set of reusable database connections.

### Why needed

Opening a DB connection involves:

- TCP handshake
    
- authentication
    
- memory allocation on DB server
    

Cost per connection is non-trivial. Repeating this per request is inefficient.

### Without Pool

```
request → open connection → query → close
(repeated for every request)
```

Issues:

- high latency
    
- resource exhaustion
    
- “too many connections” errors
    

### With Pool

```
app start → create N connections
request → borrow connection → execute → return to pool
```

### CS fundamentals

1. Resource management: finite connections allocated and reused.
    
2. Concurrency control: requests queue when pool is busy.
    
3. Reuse over creation: avoids repeated expensive setup.
    
4. Latency optimization: reduces per-request overhead.
    

### Relevance (fullstack)

- Standard in all stacks (Node `pg`, Java HikariCP, etc.)
    
- Required for scalability and production readiness.

## 6. Express Server (`index.js`)

```js
const express = require("express");
const cors = require("cors");
const pool = require("./db");

const app = express();

app.use(cors());
app.use(express.json());
```

### Middleware

1. express.json(): parses JSON request body.
    
2. cors(): allows cross-origin API calls.

## 7. Test Database Connection

```js
app.get("/", async (req, res) => {
  try {
    const result = await pool.query("SELECT NOW()");
    res.json(result.rows[0]);
  } catch (err) {
    res.status(500).send("Server Error");
  }
});
```

Flow:

```
HTTP request → Express route → pool.query()
→ connection from pool → SQL execution → result
```

## 8. CRUD APIs

### Create Task

```js
app.post("/tasks", async (req, res) => {
  const { text } = req.body;

  const result = await pool.query(
    "INSERT INTO tasks(text) VALUES($1) RETURNING *",
    [text]
  );

  res.json(result.rows[0]);
});
```

### Get All Tasks

```js
app.get("/tasks", async (req, res) => {
  const result = await pool.query("SELECT * FROM tasks");
  res.json(result.rows);
});
```

### Delete Task

```js
app.delete("/tasks/:id", async (req, res) => {
  const { id } = req.params;

  await pool.query("DELETE FROM tasks WHERE id = $1", [id]);
  res.json("Deleted");
});
```

### Key Concept: Parameterized Queries

```
VALUES($1)
```

Prevents SQL injection by separating query structure from data.

## 12. Why this Architecture

1. Separation of concerns: UI, logic, data independent.
    
2. Security: database not exposed to client.
    
3. Scalability: backend and DB scale independently.
    
4. Performance: pooling reduces overhead.
