## What is SQL?

**SQL (Structured Query Language)** is the standard language to interact with relational databases: storing, retrieving, updating, and deleting data.

- Backend code (Java/Spring Boot, Node.js/Express) connects to PostgreSQL, issuing SQL queries.
- You store application data (users, orders, blog posts, etc.) in PostgreSQL.
- As a full-stack dev, you write SQL for queries, design tables, and handle data in backend code.
## Basic Database Concepts

| Concept                    | Description(...............)                      |
| -------------------------- | ------------------------------------------------- |
| Database                   | Container for all your data (like “MyAppDB”)      |
| Table                      | Like a spreadsheet (users, posts, products, etc.) |
| Row (Record)               | A single entry (e.g., one user)                   |
| Column (Field / attribute) | An attribute of a record (e.g., username, email)  |
| Schema                     | A namespace in the database (default: “public”)   |
### KEY DATA TYPES

- `SERIAL`, `INTEGER`, `BIGINT` – for ids and numbers
- `VARCHAR(n)`, `TEXT` – strings
- `BOOLEAN` – true/false
- `TIMESTAMP` – date and time
- `JSON`, `JSONB` – structured data

### IMPORTANT CONSTRAINTS 

- `PRIMARY KEY` – unique row identifier
- `NOT NULL` – value always required
- `UNIQUE` – value must be unique
- `FOREIGN KEY` – links to another table’s primary key (for relationships)
- `DEFAULT` – auto-applied value if missing

## Core SQL commands (CRUD)
### A. create database

```sql
CREATE DATABASE myappdb
```

### B. create table

```sql
CREATE TABLE users (
	id SERIAL PRIMARY KEY,
	username VARCHAR(50) NOT NULL UNIQUE,
	email VARCHAR(255) NOT NULL UNIQUE,
	password_hash TEXT NOT NULL,
	created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

- `SERIAL`: auto-incrementing integer (Postgres shortcut)
- `PRIMARY KEY`: unique identifier per row
- `NOT NULL`: this field is required
- `UNIQUE`: value must be unique in this table
- Each RDBMS has slightly different syntax (`SERIAL`, `AUTO_INCREMENT`, `IDENTITY`, `SEQUENCE`).

### C. Inserting Data (INSERT)

```sql
INSERT INTO users (username, email, password_hash) 
VALUES ('Alice', 'alicce@gmail.com','hashedpassword123');
```

### D. Reading Data (SELECT)

```sql
SELECT * FROM users;
```

```sql
SELECT username FROM users;
```

```sql
SELECT * FROM users WHERE email = 'alice@gmail.com';
```

### E. Updating Data (UPDATE)

```sql
UPDATE users
SET email = 'alicenew@gmail.com'
WHERE username = 'alice';
```

### F. Deleting data

```sql
DELETE FROM users WHERE username = 'alice';
```

### G. Filter, Sort, Limit

```sql
SELECT * FROM users
WHERE created_at > '2025-05-05';
```

```sql
SELECT * FROM users
ORDER BY created_at DESC;
```

```sql
SELECT * FROM users LIMIT 10;
SELECT * FROM users LIMIT 10 OFFSET 10;
```

## TABLE AND SCHEMA MANAGEMENT

Part of the DDL (Data definition language) , to organize your database structure and set up relationships - critical for building real apps


### A. Modifying Tables

```sql
ALTER TABLE products 
ADD COLUMN in_stock BOOLEAN DEFAULT true;
```

```sql
ALTER TABLE products DROP COLUMN in_stock;
```

```sql
ALTER TABLE products RENAME COLUMN name TO product_name;
```

```sql
DROP TABLE products
```

### B. Schemas

- A schema is a namespace to organize tables
- by default, everything is in public schema
- For most web apps, one schema (public) is enough at first

```sql
CREATE SCHEMA admin;
CREATE TABLE admin.settings(...);
```

### C. Indexes

Indexes speed up data lookup for columns frequently searched or joined.

```sql
CREATE INDEX idx_users_email ON users(email);
```

- Indexes accelerate `WHERE` lookups and are vital for large tables.

### D. Relationships : Foreign Keys
learn more at [[2. relationships and foreign keys]]
- **One-to-many**: A product “belongs to” a user (`user_id`)
- **Many-to-many**: Use a join table

```sql
CREATE TABLE product_tags(
	products_id INTEGER REFERENCES products(id),
	tag_id INTEGER REFERENCES tags(id),
	PRIMARY KEY (product_id, tag_id)
);
```

### E. Views and Materialized Views

**View:** A saved query you can select from like a table.

```sql
CREATE VIEW user_emails
AS SELECT username, email FROM users;
```

```sql
SELECT * FROM user_emails;
```

**Materialized view:** Stores the data result set (must refresh manually).

```sql
CREATE MATERIALIZED VIEW recent_users 
AS SELECT * FROM users
WHERE created_at > CURRENT_DATE - INTERVAL '7 days';
```
